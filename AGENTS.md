# AGENTS.md

Contributor instructions for coding agents. This file is the source of truth
for how to work in this repo; CLAUDE.md imports it. Repos generated by forge
receive a copy of this file with the **Project context** section rewritten for
that project — everything below it is the durable core and travels unchanged.

# Project context

forge takes projects from specification to shipped software with quality
enforced along the whole lifecycle. A project is a trajectory, not an artifact:
each iteration must land inside an acceptance area that tightens over time.
The area is defined by deterministic gates (format, lint, types, tests,
diff-coverage) and non-deterministic gates (agent review against the project's
spec and preferences).

North stars: **flexibility, performance, quality** (quality includes
presentation). The meta-goal is measurability — changes to forge itself are
judged by how fast and how correctly an agent can make changes in the repos it
produces.

Layout:
- `src/forge/` — the package. `gates.py` is the machine-readable gate registry;
  later stages (repo generation, trajectory measurement) reason about gates
  through it, never by grepping config files.
- `tools/` — standalone gate implementations (`repo_hygiene.py`,
  `coverage_gate.sh`) shared verbatim with generated repos.
- `test/` — pytest suite. Tests pin the sync between the gate registry and the
  actual configs; breaking that sync is a test failure, not a style issue.

# Commands

Everything runs through `uv`; never invoke `pip`, `python`, or a bare venv.

| Task | Command |
|---|---|
| Install / sync deps | `uv sync --group dev` |
| Tests | `uv run pytest -q` |
| Format | `uv run ruff format .` |
| Lint | `uv run ruff check .` (add `--fix` for autofixes) |
| Types | `uv run mypy .` |
| All commit-stage gates | `uv run pre-commit run --all-files` |
| Push-stage gate | `bash tools/coverage_gate.sh` (needs `origin/main`; locally override with `DIFF_COVER_COMPARE_BRANCH=main`) |

# The gate system

- Fast gates block commits: hygiene checks, `ruff format`, `ruff check`,
  `mypy --strict`. Slow gates block pushes: pytest under coverage plus
  diff-cover requiring **≥90% coverage on changed lines**. CI re-runs
  everything on push/PR — bypassing hooks locally never lands unchecked code.
- Write code that passes the gates on the first run instead of iterating
  against them: typed throughout, no debug statements, no commented-out code,
  files end with one newline.
- Never weaken a gate to make your change pass — don't lower thresholds, add
  ignores/excludes, or `# type: ignore` without a code. If a gate is genuinely
  wrong, stop and say so; changing the acceptance area is a decision for the
  human, not a side effect of a task.
- New gates or threshold changes must update `src/forge/gates.py` and its
  tests in the same change — the registry mirrors `.pre-commit-config.yaml`
  and `.github/workflows/ci.yml`, and the test suite enforces the mirror.

# Working rules

- **Plan before code.** Read the code you're about to change; never edit from
  a guess or a grep hit alone.
- **Verify, don't declare.** A task is done when the gates pass, not when the
  edit is written. Run the relevant commands and report their real output.
- **Small, complete increments.** Each commit passes all commit-stage gates
  and contains one coherent change with its tests. No WIP commits, no giant
  final commit.
- **Tests state behavior.** Test names describe the behavior pinned, not the
  function called. A bug fix includes the regression test that would have
  caught it.
- **No defensive slop.** No `try/except` that swallows errors, no
  "for simplicity" shortcuts, no dead config knobs. Handle the cases the spec
  requires; fail loudly otherwise.
- **Comments carry constraints.** Comment only what the code cannot say —
  invariants, external contracts, non-obvious "why". Never narrate the change
  you just made or reference the session/task that produced it.
- **Names over docs.** Prefer renaming to explaining. Descriptive names
  everywhere; abbreviations only when they're the domain's own vocabulary.

# Commit messages

Imperative mood, capitalized subject, ≤50 chars, no trailing punctuation.
Body only when it adds information the subject can't: wrap at 72, blank line
after the subject, explain why rather than what.
